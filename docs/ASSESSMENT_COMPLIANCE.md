## Architecture and interfaces

The engine → adapter → domain service → UI separation is appropriate. Keep scheduling independent of React/database packages. A deterministic greedy heuristic is allowed by the assignment; exhaustive search, AI, optimality and solver certificates are not required.

The backend contract (`/data/reviews/v040-backend-contract.md`) is now backed by inspected implementation and the passing real-PG cases in the second-check log. Remaining deployed acceptance must still exercise these seams:

1. **State isolation:** the existing service has module-global `workspaceStore`. `server/bridge.ts` currently imports/applies/exports in a synchronous `try/finally` and clears to blank. Never await or retain per-request state inside this bridge. Test interleaved requests for two workspaces and failure cleanup. A request-scoped domain service is the safer future architecture, not a mandatory rewrite for this assessment.
2. **Transaction authority:** read current document + check expected revision + validate proposal + write new document/history must be one DB transaction. A process-local revision check is insufficient across instances. Session workspace/role comes from server authentication, not client IDs. Reject history insertion, deletion and mutation.
3. **Publication:** recompute from authoritative proposal and trusted adjacent history. Do not trust stored `coverageRate`, client `status`, old violation arrays or client-generated publication entries. Immutable snapshots need their own dataset/config for independent historical audit.
4. **Async UI seam:** new `run(action, message): Promise<boolean>` must be awaited at conditional callers; disable duplicate controls while busy; rollback/reload on 409; signal save failures without false success. Remove misleading browser-local labels only after central persistence is actually active.
5. **Limits:** frozen bridge caps documents at 24 months and publications at 100, while portable service allows 10,000 publications and QA-08 uses 101. README now discloses this scope and server-policy test preflights graceful atomic rejection at 101; existing history remains intact. UI imports are capped at 1.8 MB against a 2 MB HTTP body limit. Do not claim indefinite history or support for all portable backups.
6. **Catalogue semantics:** frozen `management.ts` restricts deletion when referenced by eligibility, allocations/baseline or lead relationships, preserving history; management regression suite is part of the observed passing check. Current catalogue is explicitly active-month scoped in UI/README. Deployed create/edit/remove and failed-removal replay remains useful acceptance; optional CRUD alone is not evidence of central data consistency.
7. **Time/history semantics:** frozen interval/history source and passing regression suite cover incompatible overlaps independent of daily weights, overnight touched dates, exact boundaries, minimum-rest policy and recorded prior-month integration. Reproduce those configured scenarios in deployed acceptance. Calendar days, workload capacity and actual elapsed-hour rules are distinct concepts. No jurisdiction-wide labor-law compliance is established.
